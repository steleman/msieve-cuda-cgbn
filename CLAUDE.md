# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Msieve: a C library (`libmsieve.a`) plus a demo driver (`demo.c` → `./msieve`) for factoring integers with SQUFOF/tiny QS/ECM, MPQS, and the number field sieve.

**This tree is a fork** (Stefan Teleman's, to be published on his GitHub): an SVN checkout of `^/trunk` r1113 used as a local workspace, with a **git** repository on top (commit `6d4fa7e` = unmodified r1113, then one commit per change). Commit to git freely; never push, never `svn commit` — nothing goes back to upstream msieve. The fork makes NFS polynomial selection fast on NVIDIA GPUs (section **GPU polynomial selection** below); `README.md` summarizes it and `msieve-gpu-design.tex` / `.pdf` is the design document (pdflatex twice; keep it in step with the code). The note in upstream's own copy of this file about `../msieve-polysize` (another branch, with the `rsa*` test inputs) does not apply on this machine.

Background docs in the tree: `Readme` (general use), `Readme.nfs` (the NFS workflow, intermediate file formats, and every `-np`/`-ns`/`-nc` option string), `Readme.qs`, `Changes`.

## Build

```sh
make all                  # builds libmsieve.a and ./msieve
make all ECM=1            # link GMP-ECM (-lecm), enables ECM
make all CUDA=12          # or 13; GPU build (CUDA=12 builds sm_60..75 and, since Nov 10, sm_80..120 too: tested with CUDA 12.9)
                          # here: PATH=/usr/local/cuda-13.2/bin:$PATH make all CUDA=13
make all VBITS=256        # linear algebra vector width: 64 (default), 128, 256
make all NO_ZLIB=1 / MPI=1 / BOINC=1
make clean
```

Plain `make` only prints help. Requires GMP, zlib and pthreads (and CGBN headers for the GPU size optimization: `CGBN_INCLUDE`, default `/usr/local/include`). `CFLAGS` uses `-O3 -march=native -DNDEBUG` plus `STD_FLAGS = -std=c11 -D_GNU_SOURCE -D_DEFAULT_SOURCE` and `WARN_FLAGS = -Wall -W -Wpedantic -Wstrict-prototypes -Wold-style-definition -Wmissing-prototypes -Wno-overlength-strings`. **All three builds (`CUDA=13`, CPU-only, `ECM=1`) have zero warnings; keep it that way** (`make clean` between them). `-std=c11` also turns off GCC's floating-point contraction, which matters (see below). `MACHINE_FLAGS` is for the user (e.g. `-DQ_ROOTS_MIN=1`). On this Linux machine `gcc` is GCC 14; upstream's note said macOS / Apple clang.

Header dependencies are coarse. Each object group depends on all of its group's headers, so editing a header in `include/` rebuilds nearly everything. Object suffixes: `.o` for `common/`, `.qo` for `mpqs/`, `.no` for `gnfs/`. `mpqs/sieve_core.c` is compiled twice (32k and 64k block sizes) under different `ROUTINE_NAME`s.

**A new source file must be added to the right list in the Makefile** (`COMMON_SRCS`, `QS_SRCS`, `NFS_SRCS`, or the `*_GPU_SRCS`/`*_NOGPU_SRCS` variants). The Visual Studio project directories (`build.vc*`, `build.cuda.vc*`, `build.vs`, `build.cuda.vs`) have their own file lists.

There is no test suite. Changes are checked by running the binary on real inputs and comparing outputs (see **Verifying changes**). `worktodo.ini` is the default input file.

## Running

```sh
./msieve -h                               # all options
./msieve -v <N>                           # factor N, logging to screen and msieve.log
./msieve -v -np1 -nps <N>                 # poly selection stage 1 + size optimization only
./msieve -v -nps -s <name> <N>            # size-optimize hits in <name>.m → <name>.ms
./msieve -v -npr <N>                      # root-optimize <dat>.ms → <dat>.p and the .fb file
./msieve -v -np "polydegree=5 min_coeff=X max_coeff=Y stage2_norm=Z" <N>
```

Integers can be expressions, e.g. `"(10^53-1)/9"`. Defaults: log file `msieve.log`, data file `msieve.dat` (with derived files `msieve.dat.m`, `.ms`, `.p`, …), factor base file `msieve.fb`. All NFS options go in **one** quoted string, even when several stage flags are given. NFS poly selection and sieving run only for inputs above about 85 digits.

## Architecture

- **Public API** (`include/msieve.h`): `msieve_obj_new(...)` → `msieve_run(obj)` → `msieve_obj_free`. All state lives in the `msieve_obj`. Which stages run is controlled by `MSIEVE_FLAG_*` bits, e.g. `MSIEVE_FLAG_NFS_POLY1` / `NFS_POLYSIZE` / `NFS_POLYROOT` / `NFS_SIEVE` / `NFS_FILTER` / `NFS_LA` / `NFS_SQRT`; the demo maps `-np1`/`-nps`/`-npr`/`-ns`/`-nc1`… onto these. Options arrive as a free-form `name=value` string that each module parses.
- **Dispatch** (`common/driver.c`): trial division and small methods (`common/smallfact/`: SQUFOF, tinyqs, optional GMP-ECM), then MPQS (`mpqs/`) or NFS (`gnfs/gnfs.c`) depending on size.
- **Shared back end** (`common/`): filtering (`common/filter/`: singletons, cliques, merge), block Lanczos (`common/lanczos/`, vector width set by `VBITS`, optional MPI), batch factoring, savefile I/O (gzip-aware), `mp.c` (its own fixed-size multi-precision type `mp_t`, used alongside GMP), `dd.h` (double-double), and numerical helpers (`minimize.c`, `integrate.c`, `polyroot.c`, `dickman.c`).
- **NFS** (`gnfs/`): `poly/` (selection) → `sieve/` (line siever) → `filter/` (NFS-specific duplicate and singleton passes, feeding the common filter) → LA (common) → `sqrt/`.
- **Polynomial selection** (`gnfs/poly/`). `poly.c` drives it; `poly_skew.c` holds the degree 4–6 search. `poly_param.c` has the per-size default parameter tables (stage 1/2 norms, deadlines, E-value cutoffs), and `size_score.c`/`root_score.c` do the scoring (Murphy E, alpha).
  - `stage1/`: collision search for leading coefficient a_d plus a linear polynomial. The CPU version (`stage1_sieve_cpu.c`) and the GPU version (`stage1_sieve_gpu.c` + `stage1_core_gpu/*.cu`, sorting via `cub/`) are mutually exclusive at build time. Output goes to `<dat>.m`, one line per hit: `a_d R1 R0`.
  - `stage2/`: `stage2.c` holds the `poly_sizeopt_*` and `poly_rootopt_*` entry points. Size optimization (translation, skew and rotation that minimize a norm) is in `optimize.c`, with a separate degree-6 path in `optimize_deg6.c`; root sieves for each degree are in `root_sieve_*.c`.

## Conventions

K&R-ish C with tab indentation and the opening brace on the function signature line; static helpers have their return type on the line above. Integer types: msieve's own (`uint32`, `uint64`, `int32`, …, the same types as `<stdint.h>`'s on Linux) in msieve's files and in every declaration other files see; the files this fork reworked (`poly_skew.c`, `stage1.c`, `stage1_sieve_gpu.c`, `stage1_roots.c`, `stage1_sizeopt_gpu.{c,h}`) use C99/C11 idioms inside: `<stdint.h>`/`<stdbool.h>` names, declarations at first use, loop-scoped counters, `static inline`, designated initializers. Keep msieve's names at the boundary (`stage1.h`, `poly_skew.h`, structs shared with `.cu` code). Allocate with `xmalloc`/`xcalloc`/`xrealloc`. Log through `logprintf(obj, ...)` so that `-q`/`-v` are respected. Each of msieve's own files starts with the public-domain header block; the files this fork adds (`stage1_sizeopt_gpu.{c,h}`, `stage1_core_gpu/sizeopt_core.{cu,h}`) carry an MIT header, Copyright (c) 2026 Stefan Teleman, and new files get that header. Functions are separated by `/*---...---*/` rule lines.

## GPU polynomial selection (this fork)

Hardware here: RTX PRO 4500 Blackwell (sm_120, 32 GB), CUDA 13.2, i9-13900K (32 threads). The build writes `stage1_core_sm*.ptx` and `sizeopt_core_sm*.ptx`; **msieve loads them from the current directory** (copy them next to the binary in every run directory, or you silently run old kernels; the lattice siever now refuses a mismatched `lasieve_core` PTX via `la_abi` = {`LA_ABI`, sizeof(la_batch_t)} and falls back to the line siever: raise `LA_ABI` in lasieve_core.h whenever a kernel's arguments change). The first run after a rebuild spends ~7 s JIT-compiling the size-optimization PTX.

Pipeline (`-np` = stage 1 + size optimization + root optimization):

- **Stage 1** (`gnfs/poly/stage1/stage1_sieve_gpu.c`, kernels in `stage1_core_gpu/stage1_core.cu`): special-q are enumerated by `MSIEVE_Q_THREADS` producer threads (default 4; `sieve_fb_clone` partitions the q by factor) into a ring of batches; per batch the GPU lifts the special-q roots mod q² (`lift_qroots_q32`), transforms, sorts and finds collisions into `found_array` (`FOUND_ARRAY_SIZE` = 2²⁰; it was 1000, and every hit past 999 per batch was silently dropped). Host root arithmetic is 64-bit / Montgomery (`stage1_roots.c`: `lift_roots_64`, `mont64_*`, incremental Garner CRT `get_enum_roots_crt`).
- **Size optimization on the GPU** (`stage1_sizeopt_gpu.c` + `stage1_core_gpu/sizeopt_core.cu`; default on for degrees 4 and 5, `MSIEVE_GPU_SIZEOPT=0` to disable): `so_run_batch` rebuilds each collision on the device (handle_collision + pol_expand + check_poly in CGBN, 512 or 1024 bits by `bits(trans_N)+16`) into slots; `so_flush` (when 8× the resident thread count are collected, and at the end of each coefficient) runs ten rounds of `so_minimize_4/5` (msieve's `minimize()` as a resumable state machine) + `so_update` (exact integer rotation/translation), then `so_finish` (projective alpha, loose bound) and `so_gather`; survivors go to the stage 2 pool via `stage1_sizeopt_submit()` → `poly_skew.c`'s `stage1_sizeopt_callback` (exact bound with the host's `exp`) → root optimization. Only ~1 in 4000 collisions leave the GPU.
- **GPU line siever** (`gnfs/sieve/sieve_core.{cu,h}`, `sieve_line_gpu.c`; structs shared with `sieve_line.c` in `sieve_line_int.h`): `do_line_sieving` calls `line_sieve_gpu()` first in CUDA builds (`MSIEVE_GPU_SIEVE=0`: CPU). It must give the CPU siever's candidates exactly: byte sums mod 256, cutoffs from the exact norm bit sizes (`ls_bits`, 384-bit Horner; host guard `ls_norms_fit`), one log base per `LOG_UPDATE_RATE` lines. Verify with `MSIEVE_SIEVE_DUMP=<file>` (both sievers) plus a relation compare with each side's primes sorted (c95 in `../runs/sieve`: identical at b 1-300 and 1000-2000). Host factoring threads must not call `eval_poly` (it keeps temporaries in the shared `mpz_poly_t`: that was a realloc crash); use `ls_eval`. Candidates are flushed per chunk and a chunk that overflows `LS_MAX_CANDS` is redone line by line (b = 1 had 80,000 in a chunk). The GPU sieves chunk k+1 while the host factors chunk k (double buffers). `batch_factor.c`'s remainder tree is threaded (`MSIEVE_BATCH_THREADS`, output under a mutex) for both sievers. On short ranges the host is the limit (~60% host factoring); over the whole c95 (b to 15M, 33,210 s) two thirds is waiting for the GPU.
- **GPU lattice siever** (`gnfs/sieve/lasieve_core.{cu,h}`, `sieve_lattice_gpu.c`; MIT): the default for `-ns` in GPU builds (`-ns "q0,q1"` = special-q; `-ns "line ..."` GPU line siever, `MSIEVE_GPU_SIEVE=0` CPU line siever; a bare `-ns` takes N as its argument, so give a range or use `-n`); resume point `<savefile>.lattice`; falls back to the line siever if it cannot run. `la_cofactor` (CGBN 256-bit, TPI 4; Fermat at 128 bits) does the host's algebraic + Fermat tests: only ~2.8% of `la_filter`'s survivors reach the host. Host jobs overlap the next GPU batch (two pinned slots, one host job at a time) and batch factoring runs in a background thread on a second `relation_batch_t` (shared savefile lock `la_save_lock`); the stop test estimates pending batch yield. Divisors in device trial division must be compile-time constants (a `__constant__` table doubled `la_filter`). c95: sieving 43.7 s, `./msieve -n` 67.8 s.
- **Postprocessing** (`gnfs/filter/relpar.{c,h}`, `gnfs/relstore.{c,h}`; MIT): filtering passes parse relation blocks on all CPUs (per-thread polynomial copies: `nfs_read_relation`/`eval_poly` write scratch values into the polynomial), then consume results in order (output unchanged). `relstore`: a new savefile's relations are copied into memory as text under the savefile's lock (never parse in the sievers: inside batch_out_lock it serializes batch threads, outside it lock contention cost 8 s; listing small primes cost 8 s), parsed once on all CPUs at the first filtering pass (`relstore_prepare`), then every pass/matrix/sqrt reads the store via `relsrc_*`. Verify store vs file path with `MSIEVE_RELSTORE=0 ./msieve -nc` on the same savefile (the first pass's relation count differs by the appended free relations; everything after must match). c95 postprocessing up to sqrt 56 -> 31 (threads) -> 20 s (store). Square root: large products on the GPU (`gnfs/sqrt/sqrt_gpu_mul.c` + `sqrtmul_core.cu`, NTT mod three primes c*2^40+1 ported from the CADO fork, driver API + PTX with `sm_abi` check; all `mpz_mul` in gnfs/sqrt go through `sqrt_mpz_mul`, GPU when both operands >= `MSIEVE_SQRT_GPU_MIN` (2048) limbs; `MSIEVE_SQRT_GPU_CHECK=1` compares with GMP: 38,688/38,688 equal; c120 sqrt only 33.7 -> 29.1 s, most time is relation reading and small poly products). `MSIEVE_SQRT_THREADS` (4; 8 with >= 32 CPUs since Nov 10: same mean, no second round 1 time in 16; c120 round of 8 33.8 s) dependencies at once; `nfs_read_dependencies` reads their relations in one pass (one pass each cost 2 s in file mode); workers get copies of the monic poly and of `msieve_obj` (seeds); `eval_poly_derivative` mutates its m0 argument, so it runs once before the threads. GPU builds use the NFS by default from 80 digits (msieve's NFS minimum; c80-c84 NFS 73-88 s vs MPQS 132-382 s; poly params clamp to the table's first entry up to 5 digits below); below 80 (test build `-DMIN_NFS_BITS=230`): crossover ~78 digits, NFS fails at 75/76 (no poly params; underdetermined matrix), gain at 78-79 only 17-27 s, so 80 stays (`common/driver.c` `nfs_by_default`, `MSIEVE_DEFAULT_NFS=0` for MPQS); polynomial selection's time limit is also a wall-clock end (stage 1 `wall_end`; past it `sizeopt_callback` skips root optimization) and `find_poly` retries with min E/4 if nothing was found. - **GPU linear algebra** (`common/lanczos/gpu/`, `lanczos_dispatch.c`): in CUDA builds the CPU backend's interface functions are renamed `cpu_*` (macros in `cpu/lanczos_cpu.h`) and the dispatcher picks per matrix (`la_vectors_on_gpu()`). Vector handles are device addresses; `lanczos.c`'s MPI gather/scatter and `lanczos_matmul.c`'s grid products stage through host copies (`gpu_mpi_mul`, `la_gpu_host_buf`), and `matmul_util.c`'s grid helpers always XOR/copy on the host (`h_xor`, `h_copy`). Kernels: warp per row/column, dense rows as bitmaps; a warp reduction must XOR the shuffled value in (an assignment there zeroed every product). Test with `test/lanczos` (synthetic `.mat` + `-nc2 skip_matbuild=1` + `depcheck`; `optest` compares each op with the CPU backend). `make clean` removes `COMMON_GPU_OBJS` in every configuration (a stale non-MPI `lanczos_gpu.o`, left by a `make clean` without `CUDA=`, broke the MPI build). The checkpoint calibration waits for 5 s of timing (`calibrate_later`). CUDA-aware MPI (`MPIX_Query_cuda_support`, `MSIEVE_LA_CUDA_MPI`): `gpu_mpi_mul` passes device vectors, `global_device_buffers(1)` makes `matmul_util.c` XOR/copy on the GPU (`g_xor`, `g_copy`), `la_gpu_sync()` before every MPI call (UCX copies on its own streams); the backend uses the primary context. `gather_*`/`scatter_ncols` always stage through host copies (HPC-X gave wrong data for a gather mixing device and host buffers). NCCL (`NCCL=1`, `MSIEVE_LA_NCCL=1`, `lanczos_ring.c`): rings over a transport (NCCL send/recv + GPU XOR, `ncclAllGather` + remainder broadcast; or `MPI_Sendrecv` on host buffers with `MSIEVE_LA_RING_TEST=1`, the only way to test the ring logic here); NCCL refuses two processes per GPU (no MIG on this card), so the NCCL transport is untested: keep the GPU-UUID check before `ncclCommInitRank` (a one-sided failure hung the others). Test with HPC-X: `source .../hpcx-2.50/hpcx-init.sh; hpcx_load; OMPI_CC=gcc make all CUDA=13 MPI=1`, `mpirun` through a wrapper that does the same (`runs/la/hpcx_mpirun.sh`).
- **MPI polynomial selection** (`MPI=1`, `mpirun --bind-to none`): `search_coeffs` gives process r every R-th accepted a_d; `-nps`/`-npr` input split by line (`line_index`); outputs `poly_out_name()` (rank > 0: `.mpiNN`), merged at the end of `find_poly_core` over MPI (`poly_mpi_merge_file`, `poly_mpi_merge_best`, exact hex), `.fb` by rank 0, then a barrier. `obj->mpi_local_rank/size` (driver.c, `MPI_COMM_TYPE_SHARED`) divide the node's GPUs (`gpu_select`, which also returns the sharers that divide stage 1's memory budget: 3 processes on one card ran out of GPU memory before) and default thread counts. All MPI calls are on the main thread (`MPI_THREAD_FUNNELED`).
- **Several GPUs**: `obj->which_gpu == MSIEVE_ALL_GPUS` (the command line's default; `-g N` one) uses every device. Stage 1 (`gpu_sieve_data_init`): thread t on lane t mod n, 1–4 threads per GPU, `device_thread_data_t` holds its `gpu_info` and memory share. Root optimization (`ro_gpu_init`): one `ro_gpu_t` engine per lane (`ro_engine_new`), shared `ro_queue_t`, jobs shared per lane then per thread (`lane_active`), submit broadcasts. `MSIEVE_SIMULATE_GPUS=n` maps lanes onto the device(s) for testing; results must not depend on it. `MAX_GPU` 64 (was 4, and `gpu_init` overran it).
- **Root optimization on the GPU** (default in GPU builds, `MSIEVE_GPU_ROOTOPT=0` for msieve's CPU code): `root_sieve_gpu.c` runs `poly_rootopt_run` in ucontext coroutines (`MSIEVE_ROOTOPT_THREADS` × `MSIEVE_ROOTOPT_SLOTS`, slots set up on first use, two slot groups per thread with a stream each so one group computes while the other's batch runs). The coroutines use the **batched root sieve** (`root_sieve_batch.c`, switched on per run by `rs->batched`): `compute_line_sizes()` (msieve's `compute_line_size` in lockstep, both ends at once), all norm bounds at once, degree 5 x-line sizes in rounds of stride 64/8/1 with interpolated starts, lines deferred (`rs_line_add/flush`) and candidates deferred (`rs_cand_add/flush`). Requests go through two thread-local hooks, `optimize_basic_batch_hook` (kernel `so_basic_<deg>`) and `line_sieve_batch_hook` (kernel `ls_sieve`, one block per line, tables built from `line_sieve_core.h`, the same inline code as the CPU path). `MSIEVE_ROOTOPT_BATCHED=1` runs the batched root sieve on the CPU: its results must equal the GPU's bit for bit. By default (`GPU_LATTICE=1`, `RS_GPU_LATTICE`; `GPU_LATTICE=0` for the CPU code) the lattice choice runs on the GPU too (`lt_xy`, `lt_x`, `lattice_core.h`; `rs_lattice_xy/x`), the setup keeps the roots on the GPU and CPU fallbacks fetch them (`rs_roots_need`); it is the default for the target hardware (RTX PRO 6000 Blackwell and up), though ~4% slower on the dev card. Test both builds. The polynomials kept are rotated and translated in CGBN (`rf_final`, `final_batch_hook`, request `RQ_FINAL`, ≤ `RF_MAX_JOBS` per request, the host sends parts); `rotation_t` holds x, y as int64 unless `big` (`save_rotation_si`; `rotation_mpz()` before CPU code). Every engine request kind must fit one batch or have a CPU fallback: a request that never fits waits forever (the engine thread spins). Degree 4/5 lines reach the GPU as parts (`rs_line_run` per run, all words: y_base as int64 (`xy->y_base_si`, `y_ok`), L_y, the lattice factors l1, l2 (`ls_sieve` forms L = l1·l2 in CGBN) and the CRT constants from `rs_lattice_crt`; `rs_line_parts` per line); `ls_sieve` forms x_base, resclass and y in CGBN and makes the candidates (`ls_cand_t`); the xy/x `mpz` fields are stale until `rs_xy_mpz()` / `rs_x_mpz()` (flags `mp_stale`, 0 for degree 6, which keeps its GMP): call them before any CPU code that reads them. `x->dbl_lattice_size` is `rs_lattice_d()` (truncated like `mpz_get_d`). Degree 6 (`root_sieve_deg6_xy.c`, `_x.c`): plane in words when `L_xy·L_xyz < 2^63` (`xy->d6_words`, `l_tot`, `rx_si`, `ry_si`; x CRT in `x->crt_w0/1`), x-lines as parts, mpz lazily (`d6_mpz`, `x->d6_stale`). The batched CPU sieve (`MSIEVE_ROOTOPT_BATCHED=1`) takes parts lines too (`rs_parts_mpz`, GMP), so it sieves the same lines in the same order as the GPU: keep it so, it is the bit-identity reference. Degree 6 batched: z-block y-lines via `rs_ylines_deg6` (shared `rs_lines_strided` with degree 5), planes' x-lines via `sieve_x_run_deg6_batch` (only when the whole xy run is in words). Degree-6 test data: `polydegree=6` on RSA-1024 (`-np1 -nps`, default bounds), E bound 1e-30. A polynomial's first request is its root sieve setup (`rs_setup_<bits>`, CGBN residues mod the prime powers, roots compacted in `init_sieve`'s order): the roots stay in the thread's device root area (`RS_MAX_ROOTS` per slot) for `ls_sieve`, and the host gets one copy. The last step of a root run is `optimize_final_batch()` (optimize.c): root properties of all heap entries through `alpha_batch_hook` (kernels `alpha_512/1024`, CGBN coefficients and residues, `alpha_core.h`; bit-identical), the Bernstein size score (`bs_size_<deg>` after alpha in the same stream: dd coefficients from CGBN limbs as `dd_gmp2dd`, Jenkins-Traub port, warp integral; within 1 ulp), then the Murphy E optimizations of the survivors through `murphy_batch_hook` (kernel `mf_opt_<deg>`, warp per candidate, `murphy_core.h`; E within ~1e-8, translations may differ where E is flat). Murphy batches run on a per-thread low-priority stream, polled; GPU Murphy and GPU line-candidate `optimize_basic()` are on by default for the target hardware (`MSIEVE_GPU_MURPHY=0`, `MSIEVE_GPU_LINECAND=0` for the CPU; both faster on the dev card). They used to follow the FP64 ratio (≤ 4), which the RTX PRO 6000 Blackwell (1/64) fails too.
- **Stage 2** (`poly_skew.c`): `MSIEVE_STAGE2_THREADS` workers (default: online CPUs), each with its own `poly_sizeopt_t`/`poly_rootopt_t`; outputs (`.ms`, `.p`, best-poly list, the measurement log) under `stage2_out_lock`. The `-nps` / `-npr` file paths use the same workers. `stage1_sieve_data_free` drains the stage 2 pool before freeing it (it used to drop queued work).

Other knobs: `MSIEVE_CPU_LIFT=1`, `MSIEVE_OLD_CRT=1` (old code paths, for comparison), `MSIEVE_SIZEOPT_LOG=<file>` (logs `S`/`P` lines per size-optimization survivor and `H` hit counts; measurement only), `-DQ_ROOTS_MIN=1` (full special-q search; the default is the degree, which won the end-to-end test). Stage 1 hits are echoed to stdout only with `-v`.

### Things learned

- **Floating-point contraction changes results.** GCC in GNU C mode fuses a*b+c into FMA; size optimization is sensitive (232 vs 235 survivors on the c120 coefficient). The GPU code is built `-fmad=false` and reproduces the no-contraction CPU results bit for bit; compare only against no-FMA builds (`-std=c11` is one).
- **The GPU size optimization is FP64-bound** (332 GFLOP/s without FMA on this card). What mattered: no local memory (the state machine's direction selection uses bit blends, `so_sel`, because the compiler turns an unrolled select back into a computed index and moves the whole state to memory), templates on the degree, launching only resident threads, and collecting batches (c140: 38.1 → 12.1 s). What did not: one candidate per thread (warp efficiency 0.34), dynamic fetch alone, `__launch_bounds__` register caps (spills; 31.6–37.8 s vs 22.3 s), reusing the value of a repeated rounded point (42% of evaluations, but 48 s: extra inlined copies of the step code and divergence).
- **Measure stage 2 before speeding up stage 1.** With all hits kept, stage 2 (0.29 ms per hit on one thread) was 100× stage 1; threading it was the win, and parallel hit handling inside stage 1 was slower (4/8/16 threads: 9.1/12.2/18.6 s vs 6.8 s) because of the single stage 2 queue and malloc contention.
- **Root optimization: depth, not throughput, was the problem.** At full load the GPU does `optimize_basic()` at 3.3 M calls/s (32 CPU threads: 3.0 M/s), but msieve makes ~47,000 calls per polynomial one after the other (warm-started line searches) and one call takes ~5 ms on a GPU thread, so the unchanged code ran 39× slower (449.6 s vs 11.6 s on 64 c155 polynomials). The batched root sieve cut the depth to a few hundred rounds: 195.6 → 169.6 s on a c155 coefficient, then 107.0 s with the line sieve on the GPU. Test with thousands of polynomials: 64 or 235 measure one polynomial's latency, not throughput.
- **Watch the sieve loop's registers.** `ls_sieve`'s loop needs ~75 values per thread; copying the grown line/poly structs and inlining CGBN pushed it into spills and made it 50% slower per position. The tables' layout is now in `__constant__` memory (`ls_c_end/size/step`, set by `ro_ls_tables_set`): 64 registers. Check `-Xptxas -v` after any change to that kernel, and time per phase with `clock64` in a scratch copy of the PTX (msieve loads it from the run directory).
- **Keep big integers next to the GPU work in CGBN** (the user's rule): host GMP between two GPU steps means copies both ways. The root heap's last step is one request: alpha (CGBN) → size score → (with GPU Murphy) the survivors' Murphy inputs written on the device and read there by `mf_opt` through an index list; the host uses GMP only for polynomials it saves.
- **Do not add FP64 work to a saturated GPU.** Murphy E on the GPU: the kernel alone beats 32 CPU threads (1,512 vs 1,263 candidates/s), but on the RTX PRO 4500 the GPU is already the limit with `optimize_basic` and the line sieve, and the c155 run went 107 → 170–183 s (long Murphy blocks also delay the short batches; stream priorities did not help). Integer work is different: the root properties on the GPU (CGBN residues + 32-bit root counting) use idle integer units and gave 107.8 → 102.6 s. Compare a kernel alone (dump real inputs, one launch vs 32 CPU threads) before judging it inside the pipeline.
- **CGBN loads need 16-byte alignment**, and device recursion (`get_zeros_rec`) needs a bigger stack (`cuCtxSetLimit(CU_LIMIT_STACK_SIZE)`): both showed up as illegal addresses; `compute-sanitizer` named the second (it needs the CUDA bin directory on `PATH`).
- **Time changes on the full coefficient, back to back.** The 1,500-polynomial slice varies ±10% between runs; a 5% change needs the 6,273-polynomial runs, alternated.
- **Pinned memory reallocation stalls every thread.** Growing the engine's batch buffers step by step meant 1,982 `cuMemFreeHost`/`cuMemAllocHost` calls, 500 s in `cuMemFreeHost` across threads (it waits for the GPU and holds the driver lock other threads' copies need). Size buffers once. It happened again with the root sieve setup's staging (grown at startup: ~10%; its batches are now capped). All thread buffers are allocated before any thread starts (`ro_thread_alloc`).
- **Hand out jobs by fair share.** Threads that spend long in setup found the queue empty: one thread took 39 of 155 polynomials, 82 s instead of 23 s. Each thread now takes at most ceil((running + queued) / threads).
- **`sieve_x_t.x_base` was never `mpz_init`'ed** (msieve bug). GMP grows a zeroed mpz on first write, so msieve's own code worked; `mpz_get_si` on it crashed.
- Builds include sm_90 / sm_100 PTX (Hopper, B200; loader branches in `stage1_sieve_gpu.c` and `so_ptx_name`); they are untested on real hardware here.
- GPU performance counters (`ncu`) need admin rights on this machine (`ERR_NVGPUCTRPERM`); nsys works. Use clock/counter instrumentation in a scratch copy instead.
